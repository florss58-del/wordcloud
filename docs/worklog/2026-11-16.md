**참석 확인 형식**을 새로 만들고 실제 세션(8MA8)까지 열어 두었다. 커밋 9개.

## 1차 — 발표 화면에서 단어가 잘리고 빠졌다 ★

은아님 말은 「잘리는 경우가 있는 것 같다」였다. 재 보니 세 가지가 겹쳐 있었다.

| 무엇 | 원인 |
|---|---|
| 단어가 **통째로 안 나옴** (25개 중 15개만) | `shrinkToFit`과 최소 글자 크기가 부딪혀 끝없이 되풀이 → 그리기가 죽음 |
| QR 상자 밑에 글자가 깔림 | 상자는 캔버스 위에 떠 있는데 글자는 그 자리를 피하지 않았다 |
| 가장자리에서 글자가 잘림 | 격자의 마지막 칸이 캔버스 밖으로 삐져나가 있었다 (`ngx = ceil(width / g)`) |

**가장 큰 것은 첫째였다.** wordcloud2는 자리가 없으면 가중치를 3/4로 줄여 다시 넣는데,
우리 `weightFactor`에 `Math.max(22 * dpr, …)` 바닥이 있어 **가중치를 줄여도 글자가 안 줄었다.**
`Maximum call stack size exceeded`로 그리기가 멈추고, `wordcloudstop`이 오지 않아
**화면이 투명도 0.45인 채로 남았다.** 수업 중 글자가 옅어 보였다면 이것이다.

### 결정

**`shrinkToFit`을 끄고, 다 들어가는 크기를 먼저 찾는다.** 보이지 않는 연습용 캔버스에 그려 보고
하나라도 안 들어가면 **전체를 함께 15% 줄여** 다시 본다(단어끼리의 크기 비율은 유지).
최소 크기까지 줄여도 안 되면 간격을 좁히고, 그래도 안 되면 적게 나온 단어부터 덜어낸다.
`shuffle: false` · `rotateRatio: 0`이라 배치가 결정적이어서 연습과 실제 그림이 같다.

**글자가 들어가면 안 되는 자리는 “배경과 한 끗 다른 색”으로 칠해 둔다**(`#fffffe`).
wordcloud2는 `clearCanvas: false`일 때 배경색이 아닌 칸을 찬 자리로 보고 피한다.
QR 상자 · 가장자리 여백 10px을 이렇게 막았다. 캔버스 밖 칸은 투명 픽셀이라 저절로 찬 자리가 되어
가장자리 잘림도 함께 사라졌다.

**질문이 두 줄이 되면 캔버스를 다시 잰다**(`ResizeObserver`). 「불러오는 중…」일 때 잰 크기로 그려
세로로 7% 눌려 있었다(531로 그리고 495에 표시).

### 검증

실제 그리기 코드를 그대로 떠서 헤드리스 크롬으로 그리고 **픽셀을 셌다** — 빠진 단어 · QR 밑 글자 ·
가장자리에 닿은 글자. 화면 셋(1366×768 · 1920×1080 · 1024×600) × 경우 열 가지 = 서른 번 모두 0.

## 2차 — 참석 확인 형식

은아님이 12월 2 · 3 · 4일 교육의 참석 여부를 워드클라우드로 받고 싶어 했다.
카카오톡 투표를 권했지만 **「워드클라우드로 할 거야」**. 요구가 차례로 붙었다 —
이름 칸 + 참석/불참 버튼 → 현재 응답 인원 → 안내문 → 참여 시간 → 버튼 이름 직접 정하기.

### 결정

**새 형식을 `mode`에 넣지 않았다.** 보안 규칙이 `mode`를 word/phrase/link로 막고 있어 규칙을 고쳐야 한다.
저장은 `phrase`로 두고 **질문 값 마지막 줄에 `#rsvp` 표시**를 달았다(8월의 「질문\n예시」와 같은 수).
그래서 처음에는 규칙 무수정으로 배포만 하면 됐다.

**저장되는 답은 늘 `이름 참석` · `이름 불참`이다.** 버튼 이름(`meta.yes` · `meta.no`)은 화면 글자만 바꾼다.
나중에 버튼 이름을 고쳐도 이미 받은 답이 흐트러지지 않는다.

**답 바꾸기는 같은 항목을 덮어쓴다.** 규칙이 「같은 `c`(기기)면 수정 허용」이라 링크 형식의 고치기와 같은 길을 쓴다.
한 사람이 두 번 세어지지 않는다.

**안내문 · 참여 시간 · 버튼 이름은 결국 규칙을 고쳤다**(`meta.info` · `open` · `close` · `yes` · `no`).
1000자 안내문을 담을 자리가 달리 없었다. 대신 **세션을 만든 뒤 따로 쓴다** — 한 번에 넣으면
규칙을 게시하기 전에는 세션 만들기까지 통째로 거부된다. 따로 쓰면 그 값만 실패하고 한국어로 이유가 나온다.

**참여 시간은 화면만이 아니라 규칙에서도 막는다**(`now >= open && now <= close`).
화면은 서버 시각(`.info/serverTimeOffset`)으로 판단해 이유를 알려 줄 뿐이다.

**이름은 글자만 남긴다**(한글 · 영문). 띄어쓰기 · 기호 · 점 · 숫자를 뺀다.
입력 도중에 지우면 한글 조합이 깨지므로 **누르는 순간에** 정리한다.
⚠️ 숫자도 빠지므로 동명이인을 「김민서1 · 김민서2」로 구분할 수 없다.

### 은아님이 직접 확인한 것 (실제 서버)

규칙 게시 → 세션 8MA8 생성(안내문 · 참여 시간 저장) → 연습 세션에서 **제출 · 응답 인원 · 시간 종료**.
`entries` 쓰기 규칙에 시간 조건을 붙였기 때문에 이 확인이 꼭 필요했다.
가짜 저장소로는 규칙의 논리를 흉내 냈을 뿐이라 **실제 서버에서 한 번 통과해야 믿을 수 있었다.**

## 3차 — 관리자 화면

- **세션 목록 상태 표시**: 이름 옆에 진행 중 / 종료 / 시작 전 / 삭제됨. 상태는 내 목록이 아니라 세션 쪽
  (`closed` · `meta.open` · `meta.close`)에 있어 목록을 그릴 때마다 읽어 온다
- **기본 정렬을 최신 순으로**(은아님 지시). 저장 열쇠를 `wc_admin_sort2`로 바꿔 예전에 고른 이름 순도 다시 시작한다.
  8월에 이름 순으로 바꿨던 것을 되돌린 셈이다
- **지난 세션 찾기를 달별 묶음으로**: 처음에는 닫혀 있고 누른 달만 펼친다. **펼친 상태는 저장하지 않는다**
  (「새로 접속해도 닫힘」). 찾기 버튼을 다시 누르면 통째로 닫힌다
- **미리 채우기**: `admin.html?fill=1&name=…&q=…&info=…&mode=rsvp&open=…&close=…`로 만들기 폼을 채워 둔다.
  만들지는 않는다. 은아님이 「세션 만들어 줘」라고 했지만 로그인이 없어 대신 누를 수 없었고, 이것이 가장 가까운 길이었다
- 파비콘(`favicon.svg`), 참석 확인을 고르면 제출 개수 칸이 1개로 잠김

## 함정

**`grep … && cat >> 파일 <<EOF`에서 grep이 아무것도 못 찾으면 뒤가 통째로 건너뛰어진다.**
상태 알약의 CSS를 붙이는 명령이 조용히 실행되지 않았다. 문법 검사도 통과했고 DOM 검사도 통과했다
(글자는 맞게 들어갔으니까). **화면을 찍어 보고서야** 알약이 이름에 글자로 붙어 있는 것을 봤다.
→ 「찾기」와 「쓰기」를 `&&`로 잇지 않는다. 쓴 뒤에는 **쓴 것이 들어갔는지 센다**(`grep -c`).

**세로로 쌓은 칸에서 `flex: 1` 자식은 높이가 0으로 계산된다.** 휴대폰에서 참석 칸의 이름이 불참 칸 위로 겹쳤다.
은아님 사진은 응답이 0명이라 드러나지 않았다. **빈 화면은 통과가 아니다** — 20명을 넣어 보고 찾았다.

**화면을 찍는 순간 창 크기가 흔들려 캔버스가 지워졌다.** 고친 뒤 스크린샷이 전부 빈 화면이었는데 숫자는 통과였다.
`ResizeObserver`가 다시 그리기를 예약했을 뿐이다. 그린 직후의 캔버스를 이미지로 겹쳐 두고 찍었다.

**파이썬 출력이 cp949라 한글이 깨져 보였다.** 결과가 틀린 줄 알 뻔했다. `PYTHONIOENCODING=utf-8`.

**참석 확인에서 「1인당 제출 개수」가 3개로 보였다.** 저장은 1개로 고정되는데 칸은 그대로였다.
은아님이 「이거 맞아?」라고 물었다. 무시되는 칸은 **잠그거나 감춘다.**

**주제 자리에 「질문」 두 글자를 넣은 연습 페이지를 보여 드렸다가 「주제가 안 보이잖아」를 들었다.**
연습용 값이라도 **실제처럼 생긴 글**을 넣는다. 자리 표시 글자는 빠진 것처럼 읽힌다.
